# 混沌推演 (Chaotic Reasoning)

## 概述

在信息不完整、边界模糊、存在不确定性的场景下，进行链式推理与置信度传播。

**核心原则：**
- 推演所需的每条信息必须满足「置信度 ≥ 80%」
- 低于 80% 的结果只能标注为「推测」，不能作为后续推演的依据
- 推演链式进行，结论可成为新的前提

## 何时使用

当用户提出以下类型的问题时：
- 信息不完整，需要「填补空白」
- 多个线索需要「拼凑」出完整图景
- 存在不确定性，需要评估置信度
- 需要「假设-验证」式的链式推理
- 结果可能存在多种可能性

## 推演流程

### 阶段 1：解析与分类

**输入解析：** 将用户输入分为三类

| 类型 | 说明 | 示例 |
|------|------|------|
| `FACT` | 可验证的事实/数据 | 「BTC当前价格约$105,000」 |
| `CLAIM` | 用户的声明/假设 | 「用户认为USDC将脱锚」 |
| `CONSTRAINT` | 约束条件/边界 | 「不考虑大于100万美元的持仓」 |

**置信度判定：**

1. **可验证信息** → 逐条验证，赋予实际置信度
2. **无法验证的信息** → 默认 95% 置信度（用户声称的事实）
3. **已知不确定信息** → 标注实际置信度

### 阶段 2：构建推理图

```
输入层 → 推理节点 → 结论节点
         (置信度传播)
```

**推理规则：**

```
前提A (C_A) + 前提B (C_B) → 结论X (C_X)

C_X = min(C_A, C_B) × 推导强度系数

推导强度系数:
- 强推导（逻辑必然）: 1.0
- 强相关（统计显著）: 0.95
- 中等相关: 0.85
- 弱相关: 0.70
```

### 阶段 3：链式推演

**推演模式 A（线性链）：**
```
输入A + 输入D → 结论M
结论M + 输入F → 结论N
结论M + 结论N + 输入C → 结论K
```

**推演模式 B（多源汇聚）：**
```
输入A + 输入B + 输入C → 结论M
结论M + 输入F → 结论N
结论N + 输入C → 结论K
```

**混沌补充规则：**
- 当直接信息不足时，用置信度≥80%的推论填补
- 每填补一次，置信度乘以 0.9（信息缺口衰减）

### 阶段 4：输出与标注

**输出格式：**

```
=== 推演结果 ===

## 最终结论
[结论陈述] (置信度: XX%)

## 推理链
1. [输入A] (C=XX%) + [输入D] (C=XX%)
   → [中间结论M] (C=XX%)
2. [结论M] (C=XX%) + [输入F] (C=XX%)
   → [结论N] (C=XX%)
...

## 推测（非结论，仅供参考）
[推测内容] (置信度: XX%)
推测依据: [基于哪条低置信度信息]
```

## 置信度规则

### 80% 门槛原则

```
推演依据可信度阈值: 80%

低于 80% 的信息:
- ❌ 不能作为推演的前提
- ❌ 不能产生确定性结论
- ✅ 可以产生「推测」标注输出
```

### 置信度分级

| 范围 | 级别 | 含义 |
|------|------|------|
| 95-100% | 高度确定 | 可验证的事实，默认声明 |
| 80-94% | 较确定 | 强推导，可作为推演依据 |
| 60-79% | 不确定 | 只能作为推测，不宜深推 |
| 40-59% | 高度不确定 | 弱推测，需标注来源 |
| <40% | 极不可靠 | 不采用或明确标注「猜测」 |

## 使用示例

### 示例 1：加密市场分析

**用户输入：**
```
输入1: BTC近30天涨幅超过50%（可验证）
输入2: 矿工持仓达到历史高位（置信度85%）
输入3: MVRV Z-Score > 7（可验证）
输入4: 机构投资者开始获利了结（用户观察）

约束: 仅考虑BTC现货市场

意图: 预测未来3个月BTC走势
```

**推演过程：**

```
1. 输入1(C=95%) + 输入3(C=95%)
   → 中间结论: 市场处于过热阶段 (C=90%)
   
2. 中间结论(C=90%) + 输入2(C=85%)
   → 推论: 短期回调风险上升 (C=85%) ✓ 可作为结论

3. 推论(C=85%) + 输入4(C=70%)
   → 推测: 上涨动力减弱 (C=63%) ⚠️ 仅作推测
```

### 示例 2：模糊场景下的投资决策

**用户输入：**
```
输入A: 项目代币经济模型显示私募轮成本为$0.5
输入B: 代币当前价格为$2.0
输入C: 私募轮代币5%已解锁（信息残缺，置信度60%）
输入D: 团队历史有过Rug行为（置信度75%）

意图: 评估该项目的风险
```

**推演过程：**

```
1. 输入A(C=95%) + 输入B(C=95%)
   → 结论: 私募已回本，浮盈300% (C=90%)

2. 结论(C=90%) + 输入D(C=75%)
   → 推测: 存在抛售风险 (C=68%) ⚠️ 低于80%，仅推测
   
3. 输入C(C=60%)
   → 推测: 解锁量较小，短期抛压有限 (C=54%) ⚠️ 低于80%
```

## 混沌处理策略

### 信息缺口填补

当推演需要但信息缺失时：

1. **先尝试用置信度≥80%的推论填补**
2. **若无足够置信度的推论，标注「信息缺口」**
3. **缺口填补后置信度乘以0.9**

```
信息缺口填补示例：
- 需要: X (未知)
- 可用推论: M (C=85%) → 可推断 X 大概率成立
- 填补后置信度: 85% × 0.9 = 76.5% → 仍低于80%，仅推测
```

### 多路径推演

当存在多条可能的推理路径时：

```
路径A: 输入X + 输入Y → 结论M (C=88%)
路径B: 输入X + 输入Z → 结论N (C=72%)

处理:
- 结论M → 可作为确定结论 (C=88%)
- 结论N → 仅作为推测 (C=72%)
- 若需进一步推演，只使用路径A
```

## 注意事项

1. **不要假设未提供的信息** — 明确标注信息缺口
2. **不要堆砌低置信度推论** — 低于80%不可作为新推演的基础
3. **链式衰减要明确** — 每一步都标注来源和置信度变化
4. **区分「不知道」和「推测」** — 诚实标注确定性边界
5. **混沌不是借口** — 即使信息不完整，也要给出最可能的结论并标注置信度
