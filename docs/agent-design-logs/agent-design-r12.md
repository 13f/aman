### 🎯 R12 关注点 1：半加载插件依赖 OS 进程退出回收资源，但在进程内隔离模式下不成立（🟡 中）

**场景**：
§2.5.4 Phase 2 半加载插件的资源回收策略（line 157）：

```
- 框架负责回收已分配的基础资源（进程级内存、文件描述符——OS 在进程退出时自动回收）
```

但 §4.4 插件隔离策略（lines 860-866）将 **进程内** 列为第一（默认）模式：

| 策略 | 说明 | 适用 |
|------|------|------|
| **进程内** | 同一进程，通过接口隔离 | 可信任插件 |
| 子进程 | 独立进程，IPC 通信 | 不信任插件 |
| 容器 | Docker 容器隔离 | 高风险插件 |
| WASM | WebAssembly 沙箱 | 需要轻量隔离 |

**"OS 在进程退出时自动回收" 只在子进程/容器模式下成立。** 默认的进程内模式中，Agent 进程继续运行，OS 不会自动回收半加载插件泄漏的资源。

| 隔离模式 | 进程退出？ | OS 自动回收？ | 半加载插件泄漏风险 |
|---------|-----------|-------------|-----------------|
| **进程内**（默认） | ❌ Agent 继续运行 | ❌ 不回收 | **🔴 资源泄漏**（DB 连接、文件句柄、内存） |
| 子进程 | ✅ 子进程退出 | ✅ 自动回收 | ✅ 安全 |
| 容器 | ✅ 容器退出 | ✅ 自动回收 | ✅ 安全 |
| WASM | N/A | N/A | 取决于实现 |

**💥 可能后果**：
- 在默认的进程内模式下，半加载插件泄漏的文件描述符积累 → 最终达到 `ulimit -n` 上限 → 所有文件操作失败
- 如果 on_load 建立了数据库连接（如 `init_db()`），半加载中断后连接不会关闭 → DB 连接池耗尽
- 半加载插件在进程中留下的"脏状态"（部分初始化的全局变量、已注册的回调）可能不影响其他插件，但也可能产生意外的副作用
- 进程内模式是最常用的模式（可信任插件），所以这是一个**最常用路径上的资源泄漏**

**🛠 建议**：
- 在 §2.5.4 的半加载插件资源回收描述中增加隔离模式区分：

```
半加载插件资源回收策略（按隔离模式）：
  - 子进程 / 容器模式：OS 回收子进程/容器资源（文件描述符、内存）—— 按 line 157 现有描述
  - 进程内模式（默认）：
    - 框架必须主动追踪插件已分配的资源（on_load 开始前注册资源追踪句柄）
    - 中断时：释放已追踪的文件描述符、关闭已打开的 DB 连接、释放已分配的内存
    - 建议：Plugin 的 on_load 实现应使用框架提供的资源追踪 API（如 `context.track_fd()`、`context.track_db()`），
      使框架可在中断时自动清理
    - 如果 on_load 未使用资源追踪 API：记录警告日志，依赖插件作者保证 on_load 的幂等性和可重入性
  - WASM 模式：由 WASM 运行时沙箱回收
```

- 或在 §4.4 插件隔离策略表中增加一列 `中断时资源回收方式`
- 风险清单新增 #54 项

### 🎯 R12 关注点 2：POST /agent/start 的幂等性未定义（🟢 低）

**场景**：
§9.3 定义了 `POST /agent/start` 的返回值（lines 1680-1685），但未定义当 Agent **已经在 Phase 5 运行时**再次被 start 的行为。

```
场景：
  t=0: POST /agent/start → Agent 启动到 Phase 5 → 返回 200 OK
  t=100: 操作员误操作再次 POST /agent/start
  t=100: === 行为未定义 ===
```

**可能性**：

| 行为 | 后果 |
|------|------|
| 立即返回 200 OK（幂等） | ✅ 符合直觉，但"启动事件循环"的语义与"已运行"矛盾 |
| 返回 409 Conflict（已在运行） | 调用者需要额外逻辑处理此响应 |
| 返回 200 OK + body 说明"already running" | 最精确但最不常见 |

**💥 可能后果**：
- 编排脚本/init container 在不确定 Agent 状态时调用 start → 如果返回非 200，可能误认为 Agent 异常
- CI/CD pipeline 中 restart 脚本调用 start → 如果 start 不是幂等的，脚本需要额外状态检查

**🛠 建议**：
- 在 §9.3 POST /agent/start 注释中增加一行：

```
                               #   幂等性：如果 Agent 已在 Phase 5（运行中），立即返回 HTTP 200 OK
                               #   （"启动"在已运行状态下是安全的空操作）
```

- 风险清单新增 #55 项
