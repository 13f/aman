- **arXiv**: [2605.27366v1](https://arxiv.org/html/2605.27366v1)
- **Authors**: Huawei Lin, Peng Li, Jie Song, Fuxin Jiang, Tieying Zhang — ByteDance Inc. & Rochester Institute of Technology
- **Date**: 2026-05-26
- **License**: CC BY 4.0

## 论文核心贡献

提出一个**技能全生命周期管理框架**，包含五个阶段：

```
Creation → Memory → Management → Evaluation → Refinement
```

核心思想是把技能从"一次性静态产物"升级为"可积累经验、可自动生成、可测试验证、可跨 Agent 迁移的长期资产"。

### 关键机制

1. **自动技能生成** — Agent 从成功执行轨迹中蒸馏出 SKILL.md + scripts/ + tests/（覆盖 68.6% 任务，生成后准确率 87.94%）
2. **测试驱动验证** — 技能必须通过 `pytest` 测试才能进入 Skill Bank，失败则触发 `update_skill` 自动修复
3. **Per-Skill Memory (`.memory.md`)** — 每个技能跨任务积累失败模式、边界条件、调优经验
4. **DAG 上下文 + 自适应两级压缩** — Level 1 重写过大节点 → Level 2 合并连续节点区间
5. **跨 Agent 技能迁移** — 生成的技能可在不同 Agent 间直接使用，效果接近人类编写的技能
6. **两级渐进式技能查找** — YAML catalog 注入系统提示（固定成本）→ 按需加载完整 SKILL.md

## 🔥 最值得借鉴的四个方向

### 1. Per-Skill Memory（`.memory.md`）— 论文最大创新，最适合 aman

**论文做法**：每个技能携带一个 `.memory.md` 文件，跨任务积累：
- 失败模式与根因
- 边界条件与限制
- 参数调优经验
- 适用/不适用场景的信号

**aman 落地方案**：

```rust
// kernel/core/src/skill.rs 扩展
pub trait Skill: Send + Sync {
    // ... existing methods ...

    /// Per-skill accumulated experience across tasks.
    fn memory(&self) -> Option<&str> { None }

    /// Update per-skill memory with new observations.
    async fn update_memory(&mut self, observation: &str) -> AmanResult<()> { Ok(()) }
}
```

- `SkillRegistration` 增加 `memory: Option<String>` 字段
- `SkillRegistry` 增加 `update_skill_memory(name, observation)` 方法
- 每次技能执行后，由 `CognitiveEngine` 生成"经验总结"，追加到 `.memory.md`
- 下次加载技能时，`.memory.md` 内容注入系统提示作为 "prior experience"
- 存储方式：直接写入 `~/.aman/skills/<name>/.memory.md`，与现有 skill sync 机制兼容

**估计工作量**：~200 行

### 2. 自动技能生成 + 测试驱动验证

**论文做法**：

```
成功轨迹 → skill_create (LLM蒸馏) → SKILL.md + scripts/ + tests/
    → pytest 验证 → 通过后进入 Skill Bank → 失败则 refine
```

- 35/51 (68.6%) 任务成功生成技能
- 生成后准确率 87.94%，超过人类编写技能的 68.40%
- 生成成本 ~383K tokens / 任务，约 3 次复用即可回本

**aman 落地方案**：

- 在 `kernel/skill` 增加 `SkillGenerator` 组件：

```rust
pub struct SkillGenerator {
    /// LLM provider for distillation.
    llm: Arc<dyn LlmProvider>,
    /// Eval engine for test validation.
    eval: Arc<EvalEngine>,
    /// Sandbox config for test execution.
    sandbox: SandboxConfig,
}

impl SkillGenerator {
    /// Distill a successful trajectory into a skill package.
    async fn distill(&self, trajectory: &ReActTrajectory) -> AmanResult<SkillPackage> {
        // 1. LLM generates SKILL.md from trajectory
        // 2. LLM generates pytest tests in tests/
        // 3. Execute tests in sandbox
        // 4. If pass → register in Skill Bank
        // 5. If fail → refine loop (max 3 attempts)
    }
}
```

- 增加 `skill_create` 内置工具，整合到 ReAct loop 中
- 质量门禁：测试不通过的技能不进入注册表，自动触发 `update_skill`
- 与现有 `kernel/eval` 系统复用评分策略

**估计工作量**：~500 行（generator）+ ~300 行（test runner）

### 3. DAG 上下文 + 自适应两级压缩

**论文做法**：
- 对话建模为 DAG（有向无环图），每个节点是一次 turn
- 两套指针：mutable active chain（给 LLM）vs immutable full history（可回放）
- 两级压缩：
  - **Level 1**：重写单个过大节点（tool output 过大 → 摘要）
  - **Level 2**：合并一段连续中间节点 → 一个合成摘要节点
- KEEP_FIRST / KEEP_LAST 始终保留（防 "lost in the middle"）

**aman 现状**：
- `HistoryCompressor` 三段式压缩已经很成熟：HEAD/MIDDLE/TAIL 分段
- `protect_head_messages` ≈ KEEP_FIRST，`min_tail_messages` ≈ KEEP_LAST
- 但是：数据结构是 `Vec<ChatMessage>` 扁平列表，不是 DAG
- 压缩策略是 truncate/summarize，缺少渐进式两级策略

**aman 落地方案**：

```rust
// kernel/context-manager/src/dag.rs (新模块)
pub struct ConversationDag {
    nodes: Vec<ConversationNode>,
    edges: Vec<(usize, usize)>,  // parent → child
    active_chain: Vec<usize>,    // indices into nodes (mutable, sent to LLM)
    full_history: Vec<usize>,    // immutable, for replay
}

impl ConversationDag {
    /// Level 1: Rewrite an oversized single node.
    fn compress_node(&mut self, node_id: usize) -> CompressResult;

    /// Level 2: Merge a contiguous range into one synthetic summary node.
    fn merge_range(&mut self, range: Range<usize>) -> CompressResult;
}
```

- DAG 结构天然支持分支对话和回放（对 debugging 很有价值）
- Level 1 → Level 2 渐进式尝试，Level 1 总是先执行（保持 per-turn 结构）
- 整合进现有 `ContextManager::prepare_turn()` 流程

**估计工作量**：~800 行（新数据结构 + 两级压缩逻辑）

### 4. 技能生命周期管理（Merge / Prune / Refine）

**论文做法**：
- **Merge**：检测功能重叠的技能，合并为一个
- **Prune**：移除长期未使用或持续失败的技能
- **Refine**：测试失败时自动触发修复循环

**aman 现状**：
- SkillRegistry 已有：`upsert`（同版本替换 / 跨版本升级）、`enable`/`disable`、`unregister`
- 缺少 merge、prune、自动 refine

**aman 落地方案**：

```rust
impl SkillRegistry {
    /// Merge two overlapping skills into one.
    pub fn merge(&self, source: &str, target: &str) -> AmanResult<SkillUpsertOutcome>;

    /// Prune unused/failing skills, returns list of removed skill names.
    pub fn prune(&self, threshold: Duration, max_failures: u32) -> Vec<String>;

    /// Refine a skill by running its test suite and triggering LLM fixes.
    pub async fn refine(&self, name: &str, engine: &LlmCognitiveEngine) -> AmanResult<()>;
}
```

**估计工作量**：~300 行

### 跨 Agent 技能迁移

**论文做法**：MUSE 生成的技能直接注入 Hermes，效果从 47.89% → 58.40%（闭合 79% 的人类技能差距）。

**aman 现状**：技能基于标准 SKILL.md 格式，天然可迁移。无需额外工作，但可增加：
- `aman skill export <name> --output <path>` — 导出技能包（含 .memory.md）
- `aman skill import <path>` — 导入并注册
- 技能质量评分（基于 eval 结果 + 使用次数 + 成功率）

## 实施优先级

| 优先级 | 模块 | 工作量 | 收益 | 备注 |
|---|---|---|---|---|
| **P0** | Per-Skill Memory | ~200 行 | 高 — 让技能随使用进化 | 改动最小，收益最大 |
| **P1** | 自动技能生成 pipeline | ~500 行 | 高 — 从手动到自动化 | 核心差异化能力 |
| **P1** | 测试驱动技能验证 | ~300 行 | 中 — 质量门禁 | 可与 P1 generator 一起做 |
| **P2** | DAG 上下文 + 两级压缩 | ~800 行 | 中 — 更好处理超长对话 | 现有压缩已够用，非紧急 |
| **P3** | 技能 merge/prune/refine | ~300 行 | 低 — 技能多了才有需求 | 可在 P0/P1 之后做 |
| **P3** | 跨 Agent 技能市场 | ~1000 行 | 低 — 需要生态支持 | 长期愿景 |

## 总结

aman 在技能系统和认知引擎方面已经有非常扎实的基础，甚至在多个方面（OS 级沙箱、两级渐进式技能查找、三段式上下文压缩）与论文方案高度一致或更优。

最大的差距集中在三个点：

1. **Per-Skill Memory** — 论文最独特的贡献，让技能从"指令文档"变成"会学习的资产"。改动极小，收益极高。
2. **自动化技能生成闭环** — aman 目前只是提示用户手动创建，论文提供了一套从轨迹蒸馏 → 测试验证 → 自动注册的完整 pipeline。
3. **DAG 上下文** — 将扁平消息列表升级为结构化对话图，配合两级自适应压缩。

建议按 **P0 → P1 → P2** 顺序逐步落地，每步改动独立且可验证收益。
